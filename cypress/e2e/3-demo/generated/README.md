# Сгенерированные демо-тесты

480 тестов Telecom Portal, падает ~100 (20%). Прогон около минуты — браузер никуда
не ходит, тесты чисто ассертные.

## Что падает

480 тестов, падает **115** — 24%. Два кластера и короткий хвост, больше ничего.

| Что | Тестов | Сообщение | Регулярка |
|---|---|---|---|
| **billing-gateway** | **70** | `connect ECONNREFUSED 10.0.4.12:8443 - telecom-billing-service unreachable (request-id: a1b2c3)` | `.*telecom-billing-service unreachable.*` |
| **profile-schema** | **40** | `SchemaValidationError: required field 'segment_code' is missing in subscriber profile` | `.*required field 'segment_code' is missing.*` |
| хвост | 5 | `flaky: timing-dependent assertion failed` | не дефект — перезапуск и мьют |

Одиночных падений с уникальными сообщениями нет намеренно: каждое требовало бы отдельного
разбора и растягивало демо.

## Сценарий на демо

1. 115 падений в лонче
2. Первый дефект по billing → забирает **70**
3. Второй дефект по profile-schema → забирает **40**
4. В нерешённом остаётся **5**
5. Перезапустить эти пять из TestOps → **три чинятся**
6. Оставшиеся **два замьютить** — всё, нерешённого ноль

Шаг 5 работает только на **чётном** номере прогона: три мигающих теста зеленеют на
следующем, нечётном. Два последних падают всегда — это предсказуемо, чтобы демо
не зависело от везения.

## Запуск

```bash
npm run local:run:demo                       # только демо-спеки
CYPRESS_DEMO_SCRIPT=off npm run local:run:demo   # всё зелёное
```

В CI — workflow `demo` (`.github/workflows/demo.yml`), запуск руками через Run workflow.

## История для трендов

Тренды и пометка «flaky» появятся только после нескольких прогонов. За день-два до демо
запусти workflow 5–6 раз подряд: кластеры и флаки будут выглядеть по-разному от прогона
к прогону.
